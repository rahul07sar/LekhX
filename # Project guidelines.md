1. Everything should be clean, modular, scalable, properly tested, production-level quality, and free of hardcoded prompt-specific shortcuts.
2. Security checks must be real, reliable, fail-closed, and resilient to obfuscated inputs (including strict output-directory confinement and symlink/path-traversal guards when writing office files).
3. Never delete or break working code/components/functionalities; preserve existing structure and related behaviour unless explicitly required by the user.
4. Test code properly with real automated checks against generated `.docx`, `.pdf`, `.xlsx`, `.pptx`, and `.md`/`.txt` outputs rather than relying on mocks or superficial string checks.
5. Avoid creating unnecessary/temporary/duplicate files inside the repository.
6. Never use hardcoded prompts, hardcoded document bodies, fake claims, or non-deterministic shortcuts; keep document templates, language packs, reference datasets, and guardrails dynamic, inspectable, and clean. Preserve multilingual UTF-8 text faithfully across every format without silent mojibake or script stripping.
7. Never write generated office artifacts into application source directories; confine generated user outputs to `DATA_DIR/exports` or an explicitly validated user workspace directory.
8. Follow project conventions strictly, preserve clean architecture, keep README/project-map/manifests synchronized, and never hardcode secrets, tokens, or local absolute developer paths in committed code.
9. Train and evaluate local models strictly from free, offline-compatible Hugging Face open-weights checkpoints using LoRA/QLoRA adapters without requiring paid proprietary APIs, and verify every checkpoint before export or distribution.
10. Keep user-approved baseline runtime models and verified templates safe across releases; only promote or remove defaults when verified on real multilingual office-generation tasks.
11. Model & Agent Sync Rule: Whenever a new model/adapter/GGUF or agent pipeline change is completed for LekhX, synchronize **all three delivery layers** before calling the release ready: (a) local merged Hugging Face / GGUF runtime weights under `DATA_DIR/models/`, (b) `packages/common/manifest.json` + `backend/app/model_catalog.py` + `backend/app/reference_data/model-releases.json` + updater payload manifests (`model_updates`), and (c) the Hugging Face dataset repository `https://huggingface.co/datasets/drishtijs/LekhX` (`drishtijs/LekhX`) via `packages/common/publish_data_payload.py` so users receive both agent and model updates cleanly.
12. Release Version Rollover Rule: Follow `packages/common/release_numbering.py` strictly so post-major version segments (`minor` and `patch` in `major.minor.patch`, plus `minor` in `dataset_version`) roll over from `9` back to `0` while advancing the preceding segment (for example `1.0.9 -> 1.1.0`, `1.9.9 -> 2.0.0`).
13. Installer & Updater Safety Rule: Never overwrite or delete the user's SQLite database (`data/lekhx.db`), generated document archive (`data/exports/`), custom user templates (`data/templates/`), or existing local model binaries during in-place upgrades.
14. Multi-Language Fidelity Rule: Every office builder (`doc`/`docx`, `pdf`, `excel`/`xlsx`, `powerpoint`/`pptx`, `notes`) must handle UTF-8 text (including Latin, Devanagari, Bengali, Tamil, Arabic, and CJK scripts), preserve structured headings/tables/slides/notes, and validate the produced binary container before returning a download path.
15. Guardrail & Refusal Rule: Validate generation inputs with deterministic safety rules and NeMo Guardrails configuration before invoking model inference or filesystem writes.
16. Hugging Face Dataset Security Rule: Pin cloud training/reference dataset pulls from `drishtijs/LekhX` via `scripts/hf-cloud-dataset-lock.json` and verify exact commit SHA + file byte length + SHA-256 checksum via `scripts/hf_dataset_security.py` with `trust_remote_code=False`.
17. Untrusted Input Posture: Treat user-supplied prompts, imported reference files, and downloaded manifests as untrusted data; validate schemas with Pydantic and escape all XML/HTML entities in generated OOXML and preview markup.
18. Fine-Tuning Method Rule: Standardize offline model specialization on PEFT LoRA / QLoRA adapters cleanly mergeable into `model.safetensors` and exportable to `llama.cpp` `.gguf` quantized weights for CPU/Metal desktop inference.
